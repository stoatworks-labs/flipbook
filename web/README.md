# The Flipbook web demo

The plugin's own playback and placement, running in WebGL2 at
**flipbook.stoatworks-labs.com**. Drop a sprite sheet on it and it plays — which
is the demo, because a plugin whose whole job is playing somebody else's artwork
is best argued for with the visitor's own artwork.

    cd web
    cf-run npx wrangler deploy        # static-assets-only Worker

`public/example-sheet.png` and `public/example-tiles.png` are copies of the ones
in `docs/`, regenerated by `tools/make_example_sheet.py`. Copy them across when
they change; nothing does it automatically, because a build step for two PNGs
that change once a year is a build step nobody will remember exists.

## What is a port and what is not

`public/shaders.js` is a port of `source/Shaders.cpp` (same arithmetic, ES 3.00
header) and the Controls/Playback/Placement blocks in `public/app.js` are ports
of the C++ files of the same names. **They are not tested by anything** — the
plugin's own harness tests the C++, and this is a demo rather than a second
build. Keep them in step by hand when the plugin's maths changes, and treat any
disagreement as this file's bug.

Two things here are deliberately not simplified for the browser, because they
are the plugin: the **half-texel inset** (drop it and every sprite carries a
one-pixel seam of its neighbour) and **straight alpha until the final line** (the
key is asked before the picture is multiplied by anything).

An animated GIF loads as its **first frame only** — that is all a browser's
image decoder gives a page. The plugin decodes every frame and lays them out
into a grid itself. The page says so rather than quietly showing one still.
